# Incident reports

Postmortems for production incidents — what broke, how it was detected and fixed,
and what changed to prevent a recurrence. Kept for the same reason as the ADRs:
the reasoning is more useful than the outcome, and "here's how a problem was
handled" says more than pretending nothing ever breaks.

| Date | Incident | Severity |
|------|----------|----------|
| [2026-08-20](2026-08-20-oom-wedge.md) | Instance wedged (OOM), missed ride notification | low |

Each report covers impact, detection, a timeline, root cause, resolution, and
follow-up actions.

For design decisions (as opposed to incidents), see [`../decisions/`](../decisions/).
